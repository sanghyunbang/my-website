## 시스템 구성

구성도는 [위 커버 그림](#cover)입니다. 금색이 맡은 부분이고, 웹(React)은 Spring Boot 단일 앱을 REST로 부르고, 지도는 브라우저에서 카카오 지도 SDK로 그립니다. 화살표 번호 ①–⑧은 아래 절의 번호와 같습니다.

팀 발표 자료의 구성도와는 세 군데가 다릅니다. 로그인 공급자는 네이버·구글이고, VWorld 등산로는 브라우저가 개발 프록시로 부르며(④), 예보는 서버가 받아 Redis에 씁니다.

**큐레이션 글은 두 저장소에 나뉩니다.** 제목·게시판·대표 좌표 같은 공통 정보는 MySQL `posts`에 둡니다. 구간(지점명, 설명, 좌표, 미디어 등)은 MongoDB 문서에 두고, FK 없이 앱 코드에서 `postId`로 잇습니다. 경로와 설명은 처음에 MySQL 상세 표(`curation_details`)에 두었습니다. 2025년 6월 24일부터 26일 사이에 그 내용을 MongoDB 구간 문서로 옮겼고, 그 뒤 코드는 이 표를 쓰지 않습니다.

**경로는 지점과 길이 번갈아 오는 구간입니다.** 마커 N개는 구간 2N−1개(홀수 = 지점, 짝수 = 길)가 됩니다. 마지막 지점 구간이 경로 전체를 GeoJSON `LineString`(`[경도, 위도]`)으로 가집니다. MySQL `posts.searchGeo`에는 경로 좌표 평균을 `"위도,경도"` 문자열로 둡니다.

**예보는 미리 받아 Redis에 두고, 화면 API는 Redis만 읽습니다.** 키는 `weather:{mountainNum}`이고 12시간 뒤 만료됩니다. 날씨 출처는 6월 17일에 공공데이터포털 단기예보(격자 변환)에서 기상청 API허브 산악 지점 예보(153지점)로 바꿨습니다. 산 지점 153곳은 JSON 파일을 서버 메모리에 올려 씁니다.

**지도 위 작성자는 대표 좌표 문자열로 찾습니다.** `searchGeo`를 잘라 SQL 구면 거리 3km 이내의 글 작성자를 고릅니다. 행마다 문자열을 자르고 삼각함수를 계산하므로 인덱스를 쓰지 못합니다.

## 두 흐름

번호는 [위 구성도](#cover)의 화살표 번호와 같습니다.

### 산악 예보

- **① 수집.** `WeatherScheduler`가 153지점을 5개씩 묶어 순서대로 보내고(묶음 안은 500ms 간격), 결과를 `SET weather:N … EX 43200`으로 씁니다. 6월 17일의 `for` + `Thread.sleep(800)`을 다음 날 Reactor 파이프라인으로 바꿨습니다.
- **트리거.** `@Scheduled`는 처음부터 주석이었습니다. 부팅 시 실행은 6월 18일에 켰다가 19일에 껐습니다. 커밋된 최종 코드에는 자동 갱신 경로가 없습니다(아래 한계 표).
- **② 조회.** `GET /weather/summit?mountainNum=`은 Redis만 읽어 09·15·21시 값을 날짜별로 정리합니다. 값이 없으면 200과 `error`를 돌려줍니다.
- **③ 산 검색.** 메모리 목록에서 이름으로 찾습니다(최대 10개).

### 큐레이션 글

- **⑤ 저장.** 화면이 `POST /posts/insert`로 `posts` 행을 먼저 만들고, 받은 postId로 `POST /mongo/curationSegments`(구간 JSON과 구간별 파일)를 보냅니다. 서버는 구간마다 파일을 S3에 올리고 CloudFront URL을 넣어 한 번에 저장합니다(`saveAll`).
- **⑥ 검색.** MongoDB `description` 정규식으로 postId 집합을 얻고, MySQL에서 `board_id = ? AND post_id IN (…)`으로 글을 읽습니다.
- **상세.** 화면이 글과 구간(`GET /mongo/curationSegments/{postId}`)을 따로 불러 합칩니다.
- **⑦ 지도.** 반경 3km 작성자 프로필 마커를 누르면 그 글로 갑니다.

## 인증과 미디어

- **⑧ 소셜 로그인.** OAuth2 Client로 네이버·구글 로그인을 받아 이메일로 사용자를 찾거나 만들고(닉네임 자동 생성), 액세스·리프레시 JWT를 HttpOnly 쿠키로 내립니다. 최종 화면에서 서버 흐름에 연결된 버튼은 네이버입니다.
- **요청 인증.** 요청마다 `JWTFilter`가 헤더나 쿠키의 토큰을 검증합니다. 새로고침 때는 `GET /api/user`로 로그인 상태를 되살립니다.
- **업로드.** `UUID_원본파일명` 키로 S3에 올리고, 6월 19일부터 CloudFront 주소를 돌려줍니다.
