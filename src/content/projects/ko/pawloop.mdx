## 핵심 기여 1 — 채팅 방별 순번: 동시에 보낸 메시지가 같은 번호를 받는 문제

<Callout kind="problem">

채팅방마다 메시지에 1, 2, 3… 순번을 붙입니다. 방을 읽고 +1 해서 쓰는 방식은 두 요청이 같은 값을 읽을 수 있어, 방별 순번의 유니크 제약에 걸립니다.

</Callout>

<Callout kind="solution">

`SELECT … FOR UPDATE`로 읽고 +1 해서 쓰는 방식도 요청을 한 줄로 세웁니다. 다만 행을 다시 읽어야 하고, JPA 1차 캐시의 낡은 값을 읽을 위험이 있습니다. 그래서 증가와 '내 번호 받기'를 `LAST_INSERT_ID(expr)`로 묶었습니다.

```sql
UPDATE chat_room SET last_seq = LAST_INSERT_ID(last_seq + 1) WHERE id = ?;
SELECT CAST(LAST_INSERT_ID() AS SIGNED);   -- 같은 트랜잭션, INSERT 전에
```

요청을 한 줄로 세우는 것은 UPDATE의 행 잠금입니다. `LAST_INSERT_ID(expr)`는 증가한 값을 내 세션에 남겨, 행을 다시 읽지 않고 내 번호를 받게 해 줍니다.

모바일 재전송으로 같은 메시지가 두 번 오는 경우는 방과 보낸 사람 단위 유니크 제약 `(room_id, sender_user_id, client_msg_id)`로 막았습니다. 제약 위반이 나면 그 키의 행이 실제로 있을 때만 200으로 돌려줍니다.

</Callout>

<Callout kind="result">

실제 MySQL(Testcontainers)에서 스레드 20개가 같은 방에 동시에 보내면 순번 1–20이 각각 정확히 한 번 나오는지 테스트로 고정했습니다. 커넥션 풀 기본값이 10이라 실제 동시 트랜잭션은 최대 10개입니다.

재전송 멱등은 세 경우(같은 ID 중복 / 다른 멤버의 같은 키 / 키 없음)로 고정했습니다.

</Callout>

## 핵심 기여 2 — 첫 운영 배포 사고: 통과하던 테스트가 틀린 설정에 동의하고 있었다

<Callout kind="problem">

2026-09-17 첫 운영 서버 부팅에서 컨테이너는 모두 떴는데 80·443 포트가 응답하지 않았습니다. Caddy가 설정 파싱 오류(`handle`에 경로 매처 두 개 나열)로 시작하자마자 종료돼 있었습니다.

설정을 지키던 테스트는 Caddyfile의 문자열을 검사해서, 잘못 쓴 설정도 "문자열이 있다"며 통과시켰습니다.

</Callout>

<Callout kind="solution">

운영과 같은 Caddy 이미지를 Testcontainers로 띄워 `caddy validate`를 실제로 실행하는 테스트로 바꿨습니다.

마운트 경로와 헬스체크는 compose 파일을 읽는 정적 검사로 보강했고, 문서 사이트는 렌더링을 실제로 실행해 확인합니다.

</Callout>

<Callout kind="result">

같은 주에 실행 테스트라도 운영과 다르게(복사 방식으로) 돌리면 거짓 초록이 난다는 것을 알게 되어, 기준을 '실행하느냐'에서 '운영과 같은 조건이냐'로 바꿨습니다.

</Callout>

## 핵심 기여 3 — 모듈 경계와 테스트 구조

Spring Modulith 기반 모듈러 모놀리스입니다(최상위 모듈 22개). Modulith 검사는 테스트에서 돌고, 운영 의존성에는 애너테이션 API만 들어갑니다.

- **경계 위반 래칫** — 경계 검사를 나중에 들여 위반을 **620건에서 107건**으로 줄였고, 늘어나면 테스트가 실패하도록 래칫으로 고정했습니다.
- **순환 의존과 모듈을 넘는 참조** — 모듈 간 순환 의존 0(`ModuleCycleTest`). 모듈을 넘는 FK와 조인은 기준선 테스트로 늘지 못하게 막았습니다.
- **테스트 전체 실행** — 백엔드 테스트 1,994건, 실패 0(2026-09-30, GitHub main 기준, 약 18분).
- **운영 구성** — 운영 서버는 Terraform으로 구성한 EC2 한 대이고, Caddy가 TLS를 맡는 유일한 진입점입니다. Prometheus와 Grafana는 스테이징과 로컬에만 있습니다.
- **설계 결정 기록** — 23건(대안 비교 포함 18건).
