1. 인터넷 전체에 열린 문은 Caddy(443·80) 하나입니다. SSH(22)는 지정한 IP 대역에만 엽니다. 앱 컨테이너는 호스트의 127.0.0.1:8080에만 게시하고, DB는 밖에 열지 않습니다.

3. 좌표가 기기를 떠나는 자리는 `LocationUploadPolicy` 하나입니다. 전송 여부는 컴파일 타임 상수로 정하고, 기본값은 꺼짐입니다.

- 하나의 Spring Boot 앱이고, 최상위 패키지 22개가 Spring Modulith 모듈입니다. 묶음은 반려·산책(dog, walk, walksafety), 가족·일정(group, care, schedule), 소통(chat, chatweb, crew, community, moderation, moderationweb, push), 장소(place), 계정(user, OAuth, consent), 공통(S3, security, config, error, observability)입니다.
- 모듈 경계 검사는 나중에 들인 래칫이고, 위반 기준선은 처음 620에서 지금 107입니다(모듈 간 순환 0).
- 모듈 경계를 넘는 FK는 21개이고 대부분 users와 dog로 갑니다. 테스트가 이 목록을 기준선으로 묶어 둡니다. chat 모듈은 바깥 의존이 없고(`allowedDependencies = {}`), 경계를 넘는 FK가 0입니다. 방은 가족·크루를 `origin_kind/origin_ref`로 가리키고, 일정(`owner_kind/owner_ref`)과 미디어(`ref_type/ref_id`)도 FK 없는 참조 쌍을 씁니다. 올려 두고 어디에도 붙지 않은 채 하루가 지난 미디어는 매일 04:10 정리 잡이 지웁니다.
- 모바일 재전송으로 생기는 중복은 DB 유니크 제약으로 막습니다. 산책은 `UNIQUE(dog_id, client_walk_id)`, 채팅은 `UNIQUE(room_id, sender_user_id, client_msg_id)`입니다.

- `ChatMessagePosted`: chat → push(FCM 발송)
- `ScheduleAssigned`: schedule → push(담당자에게 알림)

## 설계 결정

기획·앱·서버·인프라에 걸친 결정 네 가지입니다. 앞의 셋은 결정 기록(ADR)에 있고, 운영 바깥문의 이유는 그 구성을 만든 커밋 메시지에 있습니다.

### 위치정보: 좌표가 기기를 떠나는 자리를 한 곳으로

위치기반서비스사업 신고 전이라, 좌표가 기기를 떠나는 9곳을 `LocationUploadPolicy` 하나로 모았습니다. 전송 여부는 컴파일 타임 상수 `UPLOAD_LOCATION`(기본값 false)으로 정합니다. 서버의 경로 저장 기능은 지우지 않았습니다.

주변 장소는 전국 카탈로그를 내려받아 기기에서 거리를 계산합니다. 서버의 `walk.path`(LINESTRING, SRID 4326)에는 SPATIAL INDEX를 만들지 않았습니다. 산책을 공간 조건으로 찾는 질의가 없기 때문입니다.

대가로, 상수가 꺼져 있으면 코스 남기기와 이웃 코스 화면이 숨습니다.

### 채팅: 범용 방, HTTP 전송과 폴링, 방별 순번

방은 가족에 묶지 않고 `origin_kind/origin_ref`로 붙여 가족과 크루가 같이 씁니다. 전송은 HTTP POST이고 수신은 폴링입니다. 앱은 `GET …/messages?afterSeq=`에 `If-None-Match`를 붙이고, 새 것이 없으면 304를 받습니다. 폴링 간격은 3초에서 시작해 빈 응답마다 두 배로 늘고, 최대 30초입니다.

웹소켓과 Redis는 단일 인스턴스와 방 규모를 근거로 보류했습니다. 되돌릴 기준(빈 폴링 비율, p95, 커넥션 대기)은 ADR에 적었습니다.

커서는 `id`가 아니라 방별 `room_seq`입니다. 번호는 방 행의 잠금과 세션 값으로 한 번에 받습니다.

```sql
UPDATE chat_room SET last_seq = LAST_INSERT_ID(last_seq + 1) WHERE id = ?1
-- 같은 트랜잭션에서 LAST_INSERT_ID()로 번호를 읽고 chat_message를 INSERT
```

실제 MySQL(Testcontainers)에서 스레드 20개가 같은 방에 동시에 보내, 순번 1–20이 한 번씩 나오는지 테스트로 고정했습니다. 테스트의 커넥션 풀은 기본값 10이라, 실제로 동시에 도는 트랜잭션은 최대 10개입니다.

지운 말과 반응은 `room_seq` 델타로 오지 않습니다. 그래서 방 단위 `change_seq`를 따로 발급합니다. `room_seq`를 다시 발급하는 안은 옛 말이 맨 아래로 내려가고 미읽음이 늘어서 버렸습니다.

### 공공데이터 한도: 격자 캐시와 일일 예산

관광공사 API는 하루 1,000콜 한도가 있습니다. 그 안에서 0.02° 격자 단위 스냅샷 캐시(`place_cell`)를 두고, 일일 호출 예산(`kto_call_budget`)은 DB 행 하나의 조건부 UPDATE로 셉니다.

앱은 공공데이터 키를 갖지 않습니다. 서버가 관광공사, 두루누비, 인허가, 기상청, 에어코리아 API를 대신 부릅니다. 산책 안전 지수는 격자 번호만 받아 저장 없이 넘깁니다.

카탈로그는 새벽 04:40에 예열하고, 인허가·두루누비 데이터는 매월 1일 05:20에 갱신합니다. 대가로 외부 API 장애와 호출 비용을 서버가 집니다.

### 운영 바깥문과 서버 한 대

운영은 Terraform으로 만든 EC2 한 대의 Docker Compose입니다. 바깥문은 nginx 대신 Caddy 2.10입니다. Caddy가 인증서 자동 발급·갱신, `X-Real-IP` 주입, 약관 정적 사이트를 맡고, `/actuator/*`는 health만 통과시킵니다.

DB는 RDS가 아니라 같은 EC2의 MySQL 8.0 컨테이너입니다. 데이터 디렉터리만 별도 EBS(`prevent_destroy`)에 둡니다. 운영 설정(.env, 배포 키)은 SSM Parameter Store에 두고 부팅 때 받습니다. 설정을 고치는 길은 스크립트 하나입니다.

RDB 하나로 두고 Redis는 보류했습니다. 인스턴스가 둘이 되는 날 함께 옮겨야 할 것 네 가지(일회용 인가 코드 저장소, rate limit 카운터 등)는 ADR에 목록으로 남겼습니다. 대가는 단일 장애 지점, 배포 중 짧은 중단, 백업 절차가 없다는 점이고, 아래 한계 표에 적었습니다.
